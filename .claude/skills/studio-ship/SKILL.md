# Ship it

## Gates

```bash
pnpm typecheck        # tsc --noEmit
pnpm build            # must be clean
```

Both, every time, with the real output behind any claim that they passed. There is no
linter and no test runner in this repo; do not report one as green. If you added
behaviour worth pinning and no runner exists, say so rather than skipping it silently.

Then the app-level check from `studio-dev`: seed, mint a cookie, fetch the routes you
touched, and look at anything visual.

## Diff hygiene

```bash
git status --short
git diff --stat
git diff | grep -nE 'vs_(sk|pk)_live_|vst_|XAI_API_KEY=|AUTH_SECRET=|scrypt\$' || echo "no secret patterns"
```

- Never commit `data/`, `*.db`, `.env*` or `.vercel`. They are ignored; a forced add is
  the only way in, so do not.
- A full API key, a session token, a password hash or a model key in a diff stops the
  push. Tell the user, do not rewrite history; the credential is burned and needs
  rotating first.
- The `nextjs-agent-rules` block at the top of `AGENTS.md` is regenerated by `next dev`.
  Commit it with your work; removing it from the diff just recreates the change.
- Several agents work this repo. Check `git status` and worktrees before a broad
  refactor, and never revert work you did not write.

## Branch and PR

Two long-lived branches: `dev` integrates, `main` is production truth.

```bash
git worktree add ../voice-studio-COR-123 -b feature/COR-123-kebab-description dev
git commit -am "..."          # no AI co-author trailer, ever
git push -u origin HEAD
```

Feature branches start from `dev` and PR back into `dev`. Never commit or push directly
to `dev` or `main`, never auto-merge. Use a worktree rather than switching in place;
several agents share this repo. Open the PR with the `file-pr` skill and watch it with
`babysit-pr`. End the PR description with the model and harness line. No ticket yet:
create one on Linear team Corkkam, never invent an id. Delete the branch after merge.

## Cutting a version

Semver in `package.json`, one tag per release, tagged on `main` after the release PR
merges:

```bash
pnpm version minor --no-git-tag-version    # on the release branch
# PR dev -> main, then after it merges:
git tag -a v0.3.0 -m "v0.3.0" && git push origin v0.3.0
```

Minor for a new surface or a new `/api/v1` capability, patch for fixes and copy, major
only for a breaking `/api/v1` or SDK change. A breaking API change gets a new path
segment; never change a shipped shape in place, because the JS SDK, the Swift SDK and
the widget all call it. Say which of those clients you updated.

## Deploying

The repo is linked to the Vercel project `voice-studio`. Preview deploys are fine after
you name the blast radius, and a preview cannot hold data: the SQLite file is ephemeral
and per-instance, so treat a preview URL as a screenshot machine and say so when you
share it.

**Production is blocked on the architecture, not on permission:** the app writes to a
local SQLite file and fans out realtime events through an in-process map, so on Vercel
writes vanish with the instance and monitors miss events. Say that plainly instead of
shipping something that builds green and behaves wrongly.

Environment variables live in `vercel env` and in the local `.env.local`. Development
keys never reach production and production keys never reach a laptop. To set one, print
the command, never the value.

## Report

One consolidated message: what changed, what is verified with the command behind it,
what is left, what needs the user's hands. Caveats separate from the summary. If part of
the task is blocked, finish the rest and say exactly what you left and why.
